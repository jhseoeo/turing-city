# AI 에이전트 오토메이션 게임 기획서 (가제)

Oct 7, 2026 · @Junhyuk Seo

## 개요

**사람은 작은 보드를 조립해 마을에 배치하고, AI 에이전트가 그 보드의 펌웨어를 짜며, 기계가 일할수록 새어나오는 전자파가 러다이트를 불러온다.**

- **장르:** 오토메이션 + 마을 경영, AI 에이전트(Claude 등)로 코드를 짜는 것을 전제로 함
- **기획 의도:** 자동화 자체가 목표인 팩토리오식 구조를 피하고, 경제·최적화·위협이 하나의 시스템 안에서 유기적으로 맞물리게 한다
- **주제:** 사람이 하던 일을 하나씩 AI에게 위임해가는 이야기. 톤은 진지한 디스토피아가 아닌 우스꽝스러운 풍자
- **레퍼런스:** Factorio(오염→바이터 구조), Mindustry(자동화+디펜스), Oxygen Not Included(부산물이 문제를 만드는 구조), Shenzhen I/O(임베디드 감성), RimWorld(스토리텔러), Zachtronics 히스토그램

## 핵심 루프

1. **사람이 보드를 조립·배치**: 부품 구성, 공간 배치, 업그레이드와 재설계에 투자 *(→ 지시)*
2. **AI가 펌웨어를 작성**: 장착 부품의 API만 사용, 로그 분석, 패치 제안 *(→ 배포)*
3. **마을이 가동된다**: 자원 생산 → 업그레이드 재원, 연산량·행동량 → 전자파 누적 *(→ 전자파)*
4. **방해 요소가 들이닥친다**: 러다이트, 규제, 시세, 화재. 뉴스 피드로 미리 예고 *(→ 복구·재설계, 1로)*

마을을 돌리면 업그레이드에 쓸 자원과 위협을 부르는 전자파가 동시에 생긴다. 그래서 효율적인 펌웨어가 곧 성장이자 은신이고, 경제와 위협이 따로 놀지 않는다.

## 역할 분담

공간과 하드웨어는 사람이, 그 하드웨어 위의 소프트웨어는 AI가 맡는다. AI가 개입하는 범위를 의도적으로 좁혀서 각자의 역할이 선명하게 갈리게 한다.

| 담당 | 하는 일 |
| --- | --- |
| 사람 | 보드와 일반 블럭(벽, 밭, 벨트 등) 배치, 보드 부품 구성, 업그레이드 투자, 방향 지시, 초반 수작업, 원격 차단 구역의 직접 펌웨어 업로드 |
| AI 에이전트 | 각 보드의 펌웨어 작성과 수정, 로그·뉴스 분석, 병목 진단, 패치 제안 |
| 게임 | 시뮬레이션, 연산량·행동량 측정, 전자파 계산, 사건 발생, 결과 채점 |

플레이어 실력은 코드 문법이 아니라 "무엇을 AI에게 시킬지", "어떤 하드웨어를 줄지", "어디에 놓을지"에서 갈린다.

모든 시설은 플레이어가 직접 배치하되, 칸을 하나씩 짓지 않는다. **시설 하나와 보드 자리 하나가 묶인 블록이 배치 단위**다. 밭, 학교, 주거지역, 발전소, 쓰레기처리장, 폐수처리장 등이 모두 같은 방식이다. 공간 배치의 고민은 남기고 건설 노동은 줄인다.

## 자원과 수치

자원은 다섯 가지, 상태 수치는 세 가지로 한다. 각 수치는 최소 두 개 이상의 다른 수치와 엮인다. 부품 재료는 따로 두지 않고 돈으로 산다.

### 자원

| 자원 | 들어오는 곳 | 나가는 곳 |
| --- | --- | --- |
| 식량 | 농경 구역, 다른 마을에서 수입(비쌈) | 인구 유지 |
| 전력 | 발전 구역 | 보드와 부품 가동 |
| 돈 | 인구에 비례한 세수, 교역 | 보드·부품 구매, 수입, 세금, 유지비 |
| 인구 | 이주민 유입 | 식량 소비, 노동력, 세수의 원천 |
| 기술력 | 대학 같은 교육 시설 | 연구(신규 부품, MCP 단계 해금) |

교육 시설은 기술력을 올리지만 러다이트도 늘린다. 이상한 교육을 시키는 셈이다.

### 상태 수치

- **민심:** 주민 만족도. 자동화로 일자리를 잃은 주민이 늘면 떨어지고, 바닥나면 주민이 러다이트로 넘어간다.
- **도시평판:** 바깥의 시선. 수입 가격, 이주민 유입, 투자 조건에 영향을 준다.
- **감시도:** 정부가 마을을 얼마나 주시하는지. 플레이어에게 보이지 않는 숨은 지표다. 보드 수, 연산량, 규정 위반으로 오르고, 높으면 규제와 감사관이 오며, 끝까지 가면 강제 폐쇄된다.

전자파는 마을 전체 수치가 아니라 맵 위의 지역 값이다(전자파와 러다이트 섹션 참고).

## 시설과 물류

시설마다 핵심 메소드가 하나씩 내장돼 있고, 펌웨어는 그걸 언제 어떻게 부를지 관리한다. 시설이 무엇을 하는지는 게임이 정하고, 어떻게 운영할지는 플레이어와 AI가 정한다.

| 시설 | 핵심 메소드 | 펌웨어가 신경 쓸 것 |
| --- | --- | --- |
| 밭 | `harvest()` | 수확 타이밍, 출고함 관리, 막혔을 때 처리 |
| 발전소 | `generate()` | 발전 모듈별 출력 조절, 중단 조건, 전력 부족 시 공급 우선순위 |
| 데이터센터 | `process()` | 언제 돌리고 언제 멈출지 |
| 식량창고 | 보관·배송 | 언제 걷고, 얼마나 쌓고, 누구에게 먼저 줄지 |

역설적으로 핵심 시설일수록 코드가 단순하고, 공급망 시설일수록 복잡하다. 복잡함은 공급망에 몰린다.

### 데이터센터

마을의 주력 산업이자 경제의 종착점이다. 발전소는 전력을, 학교는 기술력을 대고, 그 모든 것이 데이터센터로 모인다.

- `process()`를 호출할 때마다 돈과 도시평판을 번다. 대신 열이 오르고 전력을 먹고 전자파가 나온다.
- 펌웨어는 센서(온도, 남은 전력, 의뢰 단가, 주변 전자파, 러다이트 접근)를 보고 호출과 중단을 정한다. 냉각을 돌리면 전력을 더 먹는다.
- 대충 짠 코드는 "80도 넘으면 멈춤" 하나로 끝난다. 잘 짠 코드는 열 관성을 감안해 미리 냉각하고, 단가 높을 때 몰아 돌리고, 위협이 오면 조용해진다.
- 로직은 단순하지만 판단 근거인 전력, 냉각, 온도가 전부 다른 시설의 운영 결과다. 데이터센터는 마을 전체가 잘 돌아가는지 비추는 거울이다.
- 돈이 몰리는 만큼 전자파 핫스팟, 해커의 표적, 화재 위험, 감시도 상승이 함께 온다.

### 물류

벨트는 쓰지 않는다. 지금 단계에서 물리적으로 움직이는 재화는 식량 하나뿐이며, 새 재화 추가는 복잡도를 고려해 신중히 한다.

1. 시설은 격자에 맞춰 배치한다.
2. 도로는 격자 사이에 알아서 있다는 설정이다. 도로 건설은 없다.
3. 밭은 수확한 식량을 출고함에 쌓는다.
4. 식량창고 보드가 밭에서 식량을 걷어와 보관하고 주거지역으로 내보낸다. 비축 상한, 부패 관리, 부족할 때의 배급 순서가 펌웨어의 몫이다. 운송 조율 시설은 움직이는 재화가 늘어나면 그때 분리한다.
5. 운송도 전력처럼 거리에 비례해 비용과 시간이 늘어난다. 트럭이나 드론이 시설 사이를 오가는 모습이 화면에 보인다.

### 전력

- 발전소는 공통 보드에 발전 모듈(풍력, 화력 등)을 붙이는 방식이다.
- 전선은 도로처럼 격자 사이에 알아서 깔려 있다는 설정이다. 송전탑 건설은 없다.
- 전력은 마을 전체로 흐르지만 발전소에서 멀수록 송전 손실이 커진다. 데이터센터를 발전소 옆에 붙이면 손실은 줄지만 전자파 핫스팟이 된다.
- 전력 저장 시설은 두지 않는다. 매 순간 발전량과 소비량이 맞아야 하고, 모자라면 공급 우선순위에서 밀린 시설부터 꺼진다.
- 제안: 풍력은 날씨에 따라 출렁이고, 화력은 안정적이지만 연료비(돈)가 든다. 바람이 셀 때 데이터센터를 몰아 돌리는 식의 운영이 생긴다.

### 부산물

- 쓰레기와 폐수는 운반하지 않는다. 처리장의 영향 반경 안 시설은 처리되고, 반경 밖이면 민심과 도시평판이 깎인다.
- 급수 시설은 두지 않는다.

## 보드와 부품 시스템

코드 블럭은 아두이노 같은 작은 마이크로컨트롤러 보드로, 플레이어가 부품을 하나씩 골라 조립한다. 보드 자체에 장착 가능한 부품 개수와 최대 전력량 한도가 있어 모든 부품을 최고급으로 채울 수 없다. 보드도 업그레이드할 수 있고, 티어가 오를수록 부품 슬롯과 전력 한도가 늘어난다. 부품 업그레이드가 성능을 올린다면, 보드 업그레이드는 그 성능을 담을 그릇을 키운다.

| 부품 | 역할 | 트레이드오프 |
| --- | --- | --- |
| 프로세서 | 틱당 연산량 상한 | 높을수록 복잡한 판단 가능, 열과 전자파 증가 |
| RAM | 실행 중 메모리 | 휴면 또는 파괴 시 내용 소실 |
| 저장장치 | 영구 메모리 | 꺼져도 남지만 읽기·쓰기에 연산을 더 소모 |
| 센서 | 블럭이 볼 수 있는 정보(토양, 전자파, 날씨 등) | 슬롯과 전력 소모 |
| 구동부 | 블럭이 할 수 있는 물리 행동(수확, 운반 등) | 행동량은 전자파에 직접 반영 |
| 통신 모듈 | 이웃 블럭과 데이터 교환, 원격 접속 | 후반 협조 플레이의 핵심 |
| 차폐 케이스 | 전자파 감소 | 슬롯 하나와 전력 소모 |

- 업그레이드한 부품은 유지비(전력, 자원)를 지속적으로 소모한다. 낮은 티어로 같은 성능을 내는 것이 고수의 영역이다.
- 핵심 선택지는 "하드웨어를 살까, 코드를 최적화할까"이다. 아낀 자원은 확장이나 대비에 쓴다.
- 에이전트는 MCP로 보드를 조회하면 장착 부품이 적힌 데이터시트를 받고, 장착된 부품에 해당하는 API만 쓸 수 있다.

## 펌웨어

펌웨어 언어는 샌드박스화한 Lua로 한다. AI가 이미 잘 아는 언어라서 게임이 문법이 아니라 로직을 시험하게 되고, 임베드가 쉽고 명령어 수 측정이 간단하다.

- **실행 모델:** 매 틱마다 `tick(io, mem)` 호출. 블럭은 정해진 입출력 포트와 장착 부품의 API만 볼 수 있고 전역 상태는 못 본다.
- **제약:** 틱당 연산량과 메모리는 장착 부품으로 정해진다. 상한을 넘으면 그 틱은 중단된다.
- **채점:** 정답 코드와 비교하지 않고 시뮬레이션 결과로 평가한다. 디자이너가 최적해를 몰라도 된다.
- **깊이 확보:** 단순한 규칙끼리 얽히게 하고, 서로 충돌하는 지표를 두고, 스케줄링·경로 탐색처럼 완벽한 해법이 없는 문제 구조를 빌려온다.
- **깊이 검증:** 같은 퍼즐을 에이전트에게 대충 시킨 결과와 신경 써서 시킨 결과의 점수 차가 크면 깊은 퍼즐이다.

### 코드 블럭 예시

| 블럭 | 입출력 | 문제 | 실력 차가 나는 지점 |
| --- | --- | --- | --- |
| 분배기 | 입력 1, 출력 3 | 품질이 제각각인 광석을 처리 속도가 다른 제련소로 분배 | 대기열 추적, 품질별 배정, 막힘 직전 우회 |
| 조립 스케줄러 | 주문 1, 재료 3, 출력 1 | 레시피 전환 시간이 있는 조립기로 마감 있는 주문 처리 | 같은 레시피 묶기와 급한 주문 끼워넣기의 균형 |
| 비축 관리자 | 센서 1, 자원 1, 출력 3 | 한정된 자원을 수리, 방어, 확장 중 어디로 보낼지 결정 | 다가오는 사건에 맞춘 전환 타이밍 |
| 드론 관제소 | 요청 1, 드론 N대 | 여러 운반 요청에 드론 배정 | 차량 경로 문제, 후반부 블럭 |

## 위임의 진행

진행은 두 축에서 동시에 일어난다. 블럭이 할 수 있는 일이 늘어나고, 플레이어와 AI 사이의 연결도 점점 직접적으로 바뀐다. 귀찮음이 쌓일수록 해금의 해방감이 커진다.

### 블럭 기능 단계 (식량 예시)

1. **T0 감지만:** 작물 상태를 읽고 알림만 보낸다. 수확은 사람이 직접 한다. 알림 로직에도 품질 차가 있다(밭 20개에서 알림 폭주를 막는 묶음 알림 등).
2. **T1 수확:** 다 자란 작물을 자동 수확한다. 재파종은 사람 몫이다.
3. **T2 재파종과 기억:** 수확, 재파종, 밭 이력 기억, 작물 선택까지 한다.
4. **T3 협조와 예측:** 여러 밭을 함께 관리하고 날씨와 사건 일정을 읽어 작물을 바꾼다.

### AI 연결 방식 해금

1. **복붙:** 게임 안 편집기만 존재. 데이터시트와 로그를 AI 채팅에 붙여넣고 받은 코드를 다시 붙여넣는다. 어떤 AI든 쓸 수 있어 진입장벽이 없다.
2. **시리얼 케이블:** 부품을 단 보드 하나에 MCP로 펌웨어를 직접 업로드한다. 로그는 못 읽는다.
3. **무선 모듈:** 범위 안의 보드들에 원격 접근한다. 범위가 있어 배치가 중요해진다.
4. **중앙 관제소:** 마을 전체 지도, 뉴스 피드, 알림 구독까지 열린다.

이 진행은 채팅창 복붙에서 에이전트가 직접 파일을 고치는 방식으로 넘어온 현실 AI 도구의 역사를 압축해서 따라간다.

## 전자파와 러다이트

기계가 일할수록 전자파가 새어나오고, 러다이트가 탐지기를 들고 그 근원을 찾아와 보드를 부순다. 위협이 바깥이 아니라 내 시스템에서 생긴다.

### 측정

코드를 해석하지 않고 실행 결과를 잰다. 엔진이 샌드박스 바깥에서 보드별로 기록하며, 보드의 메모리는 건드리지 않는다.

```latex
\text{보드 전자파} = a \cdot \text{연산량} + b \cdot \text{행동량} - \text{차폐}
```

- **연산량:** 이번 틱에 실행한 명령어 수. 이미 연산 상한을 위해 세고 있는 값이다.
- **행동량:** 수확, 운반 등 물리 행동 횟수. 기계가 대신한 노동이다.
- 행동량은 생산에 필요해 줄이기 어렵지만 연산량은 코드로 줄일 수 있다. 최적화와 은신이 같은 방향을 향한다.

### 확산

- 맵을 칸으로 나누고, 보드가 자기 칸에 전자파를 더한다. 매 틱 이웃 칸으로 번지고 서서히 감쇠한다.
- 러다이트는 전자파가 가장 강한 지점을 향해 온다. 전자파는 지역 값이며 마을 전체 게이지로 존재하지 않는다.
- 시끄러운 보드를 몰아두면 핫스팟이 되고, 흩어두면 물류가 길어진다. 배치가 평가에 엮인다.
- 전자파 히트맵은 측정기를 만들어야 보인다. 상위 티어에선 보드가 주변 전자파를 읽는 센서 API가 열린다.

### 러다이트

- 사람이 아니라 보드를 노리며, 고티어 보드가 우선 표적이다.
- 펌웨어로 대응한다: 위협 감지 시 휴면 모드, 미끼 기계로 시선 끌기.
- 포섭하면 수작업 일손이 되지만, 자동화 구역에서 일 시키면 불만이 쌓인다.
- 우두머리는 네드 러드.

## 방해 요소

평가는 별도 무대가 아니라 성장을 계속 방해하는 사건으로 이뤄진다. 원칙은 두 가지다. 사건은 내 시스템의 상태가 불러오고, 내 하드웨어와 펌웨어의 특정 약점을 찌른다. 사건마다 강한 펌웨어가 달라 단일 최적해가 없다.

### 위기 사건

| 사건 | 발동 조건 | 시험하는 성질 |
| --- | --- | --- |
| 러다이트 연합군 | 전자파 누적, 외부 세력까지 동원 | 복구력(저장장치 백업, 역할 인계) |
| 해커 | 통신 모듈로 외부와 연결된 보드가 많을수록 | 보안성(악성 펌웨어 주입, 데이터 탈취, 보드 탈취 대응) |
| AI 규제법 | 보드 수나 총 연산량이 기준 초과 | 효율성(추가 세금, 연산 상한 규제 아래서 버티기) |
| 감사관 시찰 | 규제 이후 | 규정 준수(로그 의무화로 연산 감소) |
| 월스트리트 장난질 | 시장 상황 | 적응력(부품·자원 시세 급변에 대응) |
| 번개, 화재 | 과열된 보드일수록 확률 상승 | 내결함성 |

### 규칙 변경 사건

코딩 환경 자체를 바꾸는 사건이다. 대응하려면 에이전트에게 전체 펌웨어 수정을 시켜야 한다.

- **원격 접속 차단:** 특정 구역 MCP 접근 금지. 사람이 직접 가서 케이블로 업로드해야 한다.
- **API 지원 종료:** `harvest()` 폐기, `harvest_v2()`로 마이그레이션
- **코드 길이세:** 펌웨어 한 줄당 세금
- **주석 의무화:** 가상 국가 재난 추모 주석, 일자리 영향 주석 등이 없으면 실행 거부
- **라이선스 분쟁:** 특정 내장 함수 사용 금지
- **마이너 업데이트의 배신, 금요일 배포 금지법, 레거시 인수인계, 서머타임 도입** 등

### 뉴스 피드

화면 구석에 사건의 전조가 헤드라인으로 흘러나온다. 대부분은 시시한 소식이고 가끔 진짜 위기의 예고가 섞인다. 에이전트도 MCP로 뉴스를 읽고 대비를 제안할 수 있어, 랜덤 재해가 대비할 수 있는 위기가 된다.

정치인, 기업, 국가는 모두 가상으로 만든다.

## 게임오버와 최종 목표

게임오버 조건을 먼저 정의한다. 이 장르는 엔딩보다 망하지 않고 굴러가는 과정이 본체다. 실패 경로마다 다른 약점을 찌르고, 각각 전용 엔딩 영상이 있다.

| 게임오버 | 조건 | 주로 부족했던 것 | 엔딩 영상 예시 |
| --- | --- | --- | --- |
| 물리적 함락 | 핵심 보드 전부 파괴 | 복구력 | 러다이트의 승리 행진 |
| 파산 | 자금이 일정 기간 마이너스 | 효율, 적응력 | 월스트리트 샴페인 |
| 강제 폐쇄 | 규제 위반 누적으로 영업정지 | 규정 준수 | 공무원이 보드마다 빨간 딱지 |

최종 목표 후보는 **AI에게 마을을 맡기고 은퇴하기**다. 플레이어 입력 없이 일정 기간 마을이 사건과 습격을 스스로 버티면 클리어. 위임의 진행이라는 이야기가 여기서 끝난다. 확정은 루프 검증 후에 한다.

## 연출

메카닉은 "첫 OO 달성 시 영상 재생"으로 확정한다. 구체적인 업적 목록은 나중에 채우고, 지금은 업적 이벤트가 영상을 트리거하는 구조만 있으면 된다.

- **첫 MCP 연결:** 게임의 하이라이트. "작업자가 출근했습니다". 영상 끝에 에이전트가 실제로 보낸 첫 MCP 호출을 띄워 플레이어마다 다른 장면이 되게 한다.
- **업적 영상 후보:** 첫 펌웨어 업로드, 첫 런타임 에러, 첫 보드 파괴, 첫 과열 화재, 첫 마이그레이션 완료, 첫 감사 통과 등
- **시즌 결산:** 스포티파이 랩드 패러디. 작성·삭제한 코드 줄 수, 가장 많이 고친 보드 등. 공유를 유도한다.
- **톤:** 우스꽝스러운 풍자. 개발자 공감 밈이 곧 홍보가 되게 한다.

## 기술 구조

플레이어가 각자 가진 에이전트를 쓰고, 게임은 에이전트가 상대하는 로컬 환경이 된다. 게임 쪽 AI 비용은 0이다.

- **시뮬레이터:** 결정론적 헤드리스 시뮬레이션. 설계하는 동안 세계 시간이 멈춰 있어 에이전트의 느린 속도가 문제되지 않는다.
- **로컬 MCP 서버:** 게임 실행과 동시에 로컬 포트가 열린다. 타이틀 화면에 연결 명령어 한 줄과 복사 버튼을 보여준다. 해금 단계에 따라 노출되는 MCP 도구가 늘어난다.
- **펌웨어 런타임:** 샌드박스 Lua, 명령어 수 측정, 핫리로드
- **시각화:** 공장 전경, 보드 LED와 과열 표시, 전자파 히트맵 오버레이
- **보안:** 포트는 127.0.0.1에만 바인딩하고, 실행마다 랜덤 토큰을 발급해 화면에 표시한다.

플레이어가 고르지 않은 대안: 게임이 에이전트를 제공(비용 부담), 사용자 API 키 입력(구독자 대부분이 키가 없어 진입장벽).

### 기술 스택

| 영역 | 선택 | 근거 |
| --- | --- | --- |
| 언어 | TypeScript | 시뮬레이션 코어, MCP 서버, 화면을 한 언어로 짜고 타입을 공유한다. 전부 텍스트 코드라 Claude Code로 처음부터 끝까지 개발하기 좋다. |
| 게임 프레임워크 | Phaser | 장면 전환, 애니메이션, 입력 처리 등 게임 뼈대를 갖췄다. 뱀파이어 서바이버즈가 Phaser + Electron으로 출시해 성공한 검증된 조합이다. |
| 데스크톱 래퍼 | Electron | 크롬을 통째로 포함해 OS마다 WebGL과 영상 재생이 똑같이 동작한다. Tauri는 OS 내장 웹뷰를 써서 차이가 생길 수 있다. 용량 증가는 게임에선 큰 문제가 아니다. |
| MCP 서버 | 공식 TypeScript SDK | 게임의 핵심 기능을 가장 수월하게 구현할 수 있는 언어다. |
| 펌웨어 런타임 | wasmoon(WebAssembly Lua 5.4) 등 | WebAssembly 안에서 격리된다. 명령어 수 측정이 되는지 초반에 검증한다. |
| 코드 편집기 | Monaco 또는 CodeMirror | 복붙 단계에 필요한 게임 안 편집기를 문법 강조까지 그대로 가져다 쓴다. |
| 영상 재생 | HTML video | 업적 영상과 엔딩 영상을 별도 작업 없이 재생한다. |

### 구현 원칙

- 시뮬레이션 코어는 렌더링과 완전히 분리된 순수 로직으로 만든다. 화면 없이 틱만 돌릴 수 있어야 테스트와 에이전트 기반 깊이 검증이 빠르다.
- 결정론을 위해 코어는 정수 기반으로 계산한다. 같은 입력이면 항상 같은 결과가 나와야 리플레이와 채점이 성립한다.

### 검토한 대안

- **Go + Wails:** 주 언어가 Go라 친숙하고 Lua·MCP도 무난하다. 화면은 웹으로 그리는 같은 구조라 설계는 그대로 옮길 수 있다. 언어를 하나로 통일하는 이점 때문에 TypeScript를 택했다.
- **Go + Ebitengine:** 2D 렌더링은 충분하지만 UI, 게임 안 코드 편집기, 영상 재생이 약하다.
- **Godot:** 진짜 게임 엔진이라 렌더링과 배포가 편하지만 Lua 임베드와 MCP 서버를 직접 붙여야 한다.
- **Rust + Bevy:** 성능은 최고지만 사이드 프로젝트로 시작하기엔 진입장벽이 높다.
- **PixiJS:** 렌더링 전용이라 가볍다. 게임 뼈대를 처음부터 갖추는 쪽을 택해 Phaser로 정했다.

뱀파이어 서바이버즈는 이후 성능과 콘솔 이식 때문에 Unity로 옮겼다. 이 게임은 화면 부하가 격자와 오가는 트럭 정도로 가볍고, MCP와 에이전트를 붙이는 특성상 콘솔이 주 무대가 아니라 같은 이유가 덜 해당된다.

## 구현 핸드오프

이 섹션은 구현을 맡을 Claude Code를 위한 것이다. 기획 대화에 접근할 수 없으므로, 결정과 그 이유를 여기에 모두 남긴다. **"초안"으로 표시된 항목은 기획에서 확정되지 않은 제안**이며, 구현 중 바꿔도 된다.

### 용어집

| 기획 용어 | 코드 식별자(초안) | 뜻 |
| --- | --- | --- |
| 시설 | `Facility` | 격자에 배치되는 블록. 시설 하나와 보드 자리 하나가 묶여 있다 |
| 보드 | `Board` | 시설에 꽂히는 마이크로컨트롤러. 티어, 부품 슬롯 수, 최대 전력량을 가진다 |
| 부품 | `Part` | 프로세서, RAM, 저장장치, 센서, 구동부, 통신 모듈, 차폐 케이스, 발전 모듈 |
| 펌웨어 | `firmware` | 보드에서 도는 Lua 코드. AI 에이전트가 작성한다 |
| 핵심 메소드 | `harvest()`, `generate()`, `process()` 등 | 시설에 내장된 행동. 펌웨어는 언제 부를지만 정한다 |
| 입고함, 출고함 | `inbox`, `outbox` | 시설 간 식량이 오가는 버퍼 |
| 전자파 | `emf` | 맵 칸마다 있는 지역 값. 러다이트를 부른다 |
| 감시도 | `surveillance` | 플레이어에게 보이지 않는 숨은 지표 |

### 데이터 모델 (초안)

```typescript
type FacilityKind =
  | 'farm' | 'power' | 'datacenter' | 'granary'
  | 'school' | 'housing' | 'waste' | 'sewage';

interface Part {
  kind: 'cpu' | 'ram' | 'storage' | 'sensor' | 'actuator'
      | 'comm' | 'shield' | 'genModule';
  tier: number;
  power: number;      // 소비 전력
  params: Record<string, number>; // 예: cpu.opsPerTick, ram.bytes
}

interface Board {
  tier: number;
  slotLimit: number;  // 장착 가능 부품 수
  powerLimit: number; // 최대 전력량
  parts: Part[];
  firmware: string;   // Lua 소스
  ram: unknown;       // 휴면·파괴 시 소실
  storage: unknown;   // 영구, 접근 비용 큼
}

interface Facility {
  id: string;
  kind: FacilityKind;
  x: number; y: number;
  board: Board | null;
  inbox: number;  // 식량 수량
  outbox: number;
}

interface WorldState {
  tick: number;
  facilities: Facility[];
  resources: { food: number; power: number; money: number;
               population: number; tech: number };
  status: { morale: number; reputation: number;
            surveillance: number }; // surveillance는 UI 비노출
  emf: number[][];   // 격자 칸별 전자파
  // 운송 중인 트럭·드론, 러다이트, 예정 사건, 뉴스 등
}
```

수치는 결정론을 위해 정수로 다룬다.

### 펌웨어 API (초안)

```lua
-- 매 틱 호출된다. io는 장착 부품에 해당하는 기능만 노출한다.
function tick(io, mem)
  -- io.call("harvest")      시설 핵심 메소드 호출
  -- io.sensor("temp")       장착된 센서 값 읽기
  -- io.outbox.count()      출고함 수량
  -- io.notify("msg")        플레이어 알림 (T0 단계)
  -- io.sleep(n)            n틱 휴면
  -- io.store.read(k) / io.store.write(k, v)  저장장치 접근 (연산 비용 큼)
  -- mem: RAM. 크기 상한은 RAM 부품으로 정해진다
end
```

- 틱당 실행 명령어 수가 프로세서 상한을 넘으면 그 틱은 중단된다.
- 엔진은 샌드박스 바깥에서 보드별 연산량과 행동량을 기록한다(전자파 계산용).
- 장착되지 않은 부품의 기능을 부르면 오류가 난다.

### MCP 도구 (초안)

게임 실행 시 127.0.0.1에만 로컬 MCP 서버를 열고, 실행마다 랜덤 토큰을 화면에 띄운다. 노출되는 도구는 해금 단계에 따라 늘어난다.

| 해금 단계 | 열리는 도구 |
| --- | --- |
| 복붙 | 없음. 게임 안 편집기와 데이터시트·로그 복사 버튼만 제공 |
| 시리얼 케이블 | `get_datasheet(boardId)`, `deploy_firmware(boardId, code)` (케이블 연결된 보드만) |
| 무선 모듈 | `list_boards()`, `read_logs(boardId)` (범위 안 보드) |
| 중앙 관제소 | `get_map()`, `get_status()`, `read_news()`, `subscribe_alerts()` |

원격 접속 차단 사건이 터지면 해당 구역 보드는 도구 대상에서 빠진다.

### 틱 처리 순서 (초안)

1. 사건과 뉴스 처리
2. 발전량 계산(발전 모듈별 출력, 날씨)
3. 전력 배분(거리별 송전 손실, 부족 시 우선순위 낮은 시설부터 차단)
4. 각 보드 펌웨어 실행(연산 상한 적용, 연산량 기록)
5. 핵심 메소드 결과 적용(수확, 발전, 데이터센터 수입 등)
6. 운송 진행(트럭·드론 이동, 거리 비례 시간·비용)
7. 전자파 방출, 이웃 칸 확산, 감쇠
8. 인구의 식량 소비, 민심·도시평판·감시도 갱신
9. 러다이트 이동과 공격
10. 게임오버 판정, 업적 판정과 영상 트리거

### 결정 기록

| 주제 | 채택 | 기각된 대안과 이유 |
| --- | --- | --- |
| AI 제공 방식 | 플레이어가 자기 에이전트를 로컬 MCP로 연결 | 게임이 AI 제공(비용), 사용자 API 키 입력(구독자 대부분이 키가 없음) |
| 시간 구조 | 설계하는 동안 세계 시간이 멈추는 결정론 시뮬레이션 | 실시간(에이전트가 느려서 궁합 나쁨) |
| 게임의 목표 축 | 경제·위협이 한 시스템 안에서 맞물림 | 팩토리오식 자동화 자체가 목표, 인구·장기 생존이 목표, 원정·전투 별도 무대(재미가 분절됨) |
| AI의 범위 | 보드 펌웨어만. 배치와 하드웨어는 사람 | AI가 전부 하는 구조(플레이어 할 일이 사라짐) |
| 위협 지표 | 전자파(연산량·행동량 기반) | 소음(소프트웨어가 소음을 낸다는 게 납득 안 됨), 코드 정적 분석(어려움), 티어 기반(부정확) |
| 시설 배치 | 시설 + 보드 자리가 한 블록 | 경작지 칸 하나하나 배치(건설 노동 과다) |
| 물류 | 격자 사이 자동 도로, 식량창고 펌웨어가 운송 통제 | 팩토리오식 벨트(가장 피하고 싶은 요소) |
| 창고 | 보관과 배송을 식량창고 하나로 통합 | 운송관제소 분리(움직이는 재화가 식량뿐이라 과함) |
| 재화 추가 | 신중히. 연료·냉각수·부품 재료는 두지 않음 | 부품 재료는 돈으로 통합 |
| 전력 | 자동 전선, 거리 비례 송전 손실, 저장 없음 | 송전탑 건설, 발전소 반경(욱여넣기 퍼즐이 됨) |
| 부산물 | 처리장 영향 반경 | 운반 대상화(새 재화가 생김) |
| 데이터센터 | 내장된 `process()`를 언제 부를지 관리하는 주력 산업 | 마을 안 AI 그 자체(현실 AI와 메타가 섞임), 의뢰마다 코드 작성(펌웨어는 반영구라 일시적 의뢰와 안 맞음) |
| 펌웨어 언어 | 샌드박스 Lua | 낯선 어셈블리(AI가 헤매는 게 노이즈가 됨) |
